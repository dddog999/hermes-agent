# GSD Pitfalls (积累自实战)

## 不要创建重复的数据路径

**触发场景**：GSD quick task 中，需要处理已经存在于某处（export-wiki 输出）的数据时。

**错误做法**：为了"方便后续处理"，在别处创建新的中间目录（如 `~/.clawmem/l2-history-flat/`）。

**正确做法**：
1. 先确认数据是否已存在于某个已知路径
2. 如果存在，修复工具让工具直接读那个路径
3. 不创建新目录

**检查清单**：创建新数据目录前，问"这个数据是否已存在于其他地方？"

---

## Pattern 调试优先用 node -e

**触发场景**：CLI 工具的正则/逻辑 bug，不确定是工具问题还是数据问题。

**错误做法**：反复跑 CLI 看输出，CLI 可能因为 tty 缓冲、超时等原因卡住。

**正确做法**：用 `node -e "..."` 直接测 pattern 或逻辑，跳过 CLI 层。
