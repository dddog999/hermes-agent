## Path Reference Conventions

All paths use **relative references** (CodeBuddy `@` syntax) for portability:

| Type | Original Path | CodeBuddy Path | From Context |
|------|--------------|----------------|--------------|
| Workflows | `@~/.claude/get-shit-done/workflows/` | `@../scripts/workflows/` | command file |
| Tools | `$HOME/.scripts/gsd-tools.cjs` | `@../scripts/gsd-tools.cjs` | bash blocks |
| Templates | `@~/.claude/get-shit-done/templates/` | `@../templates/` | command file |
| Docs | `@~/.claude/get-shit-done/references/` | `@../docs/` | command file |
| Agents | `@~/.claude/get-shit-done/agents/` | `@../../agents/` | command file |
| Project files | N/A | `@.planning/...` | any context |

## What Was Fixed

### 1. Agents Relocation
**Before:** Agents were duplicated inside skill at `references/agents/`  
**After:** Agents live at project root `.codebuddy/agents/` (CodeBuddy standard)

**Why:** CodeBuddy loads all agents from project `.codebuddy/agents/`, not from inside skills.

### 2. Workflow Embedding
**Before:** Workflows referenced external `@~/.claude/get-shit-done/workflows/`  
**After:**
- Physical files copied to `scripts/workflows/`
- References updated to `@../scripts/workflows/`

**Benefit:** All workflow procedures are now inside skill and versioned with it.

### 3. Tool Path Fix
**Before:** `$HOME/.scripts/gsd-tools.cjs` (absolute, depends on user home)  
**After:** `@../scripts/gsd-tools.cjs` (relative, portable)

**Benefit:** Skill works regardless of installation location.

### 4. Template & Reference Consolidation
**Before:** Mixed references to `@../docs/`, `@../templates/`, some broken  
**After:** All templating resources located in `references/{docs,templates}/` and referenced consistently.

## Key Design Decisions

1. **Agents outside skill**: Follows CodeBuddy's agent discovery pattern (`$PROJECT/.codebuddy/agents/*.md`)
2. **Workflows inside skill**: Keeps all execution logic together for versioning
3. **Project-relative references**: `.planning/` files are excluded intentionally — they bridge to user's project state
4. **No $HOME dependencies**: All home directory references converted to relative paths
5. **Single-source agents**: Only one copy of each agent at project root (no duplication in skills)
